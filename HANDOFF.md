# Handoff: Creative Performance Intelligence (v2)

Prepared 14 Nov 2026 for continuation in another agent/IDE (Antigravity). Read this first, then `README.md`.

## What this is

A static, local report site for two brands (SURYA Coffee Explorers, Monster and Friends) built from Publer post data (workspace COFFLORER). No framework, no build step, no backend.

- Status: **DRAFT, awaiting the owner's (Michael) review. Not published, not committed to git.** Do not publish or deploy without his approval.
- It is a mid-month preview. The official November report cycle starts 1 Dec and is a separate workflow (see the COFFLORER AI Workspace "START HERE" doc on Drive).

## Run it

```
python -m http.server 8766 --directory .
```

Open http://localhost:8766. (Opening `index.html` directly also works.)

Rebuild the data after changing anything in `config/` or `data/raw/`:

```
python refresh.py
```

Python 3.10+, standard library only. On Windows set `PYTHONIOENCODING=utf-8` if the console cannot print Thai.

## Layout

| Path | Role |
|---|---|
| `index.html` | The whole UI: CSS + vanilla JS in one file. Reads `window.CPI_DATA`. |
| `data/dashboard-data.js` | Generated by `refresh.py`. Never edit by hand. |
| `refresh.py` | Merges every source in `data/raw/sources.json` into the data file. |
| `data/raw/` | Raw snapshots + `sources.json` manifest. Treat as read-only; add files, never change or delete old ones. |
| `config/pillars.json` | Regex rules that tag each post with a content pillar (first match wins). |
| `config/pillar_overrides.json` | Manual pillar tags that win over the rules (all currently `confirmed` by the owner). |
| `config/insights.th.json` | Hand-written Thai analysis: executive points, per-brand findings, Gemini-vs-Claude table, data issues, recommendations, experiments. Not auto-generated. |
| `config/thumbnails.json`, `assets/thumbnails/` | Cover images keyed by `platform|post URL` (58 October posts). Images only. |
| `tools/parse_gemini_md.py` | Converts the per-post tables in Gemini's report into a supplement JSON. |

## Data model (`window.CPI_DATA`)

- `meta`: `generated_at`, `latest_post`, `latest_source_as_of`, `sources[]` (label, as_of, coverage, trust, row counts), `coverage{}` per brand|platform, `accounts[]` (weekly followers), `pillar_labels`, `pillar_overrides`, `pillar_other_share`.
- `insights`: contents of `config/insights.th.json`.
- `posts[]`: `id, brand, platform, dt (Asia/Bangkok "YYYY-MM-DD HH:MM"), format, pillar, hook, url, src, as_of, age (days between post and read), pending, thumb?, thumb_from?, reach, views, reactions, comments, shares, saves, post_clicks, link_clicks, er`. `null` = Publer did not report it.

Current contents: 1,097 deduplicated posts, 1 Jan – 13 Nov 2026.

## How the UI computes things (`index.html`)

- One state object `S` (brand view, platform, from/to, format, noRecruit, pillar, q, metric, visible) and one filter function `sel()`. Every number on the page goes through `sel()` + `stat()`. Keep it that way.
- Reporting periods are derived from `meta.latest_post` (month-to-date vs the same days of the previous month, plus the full previous month). Nothing is hardcoded to November.
- Headline figures are **medians per post**, per brand and platform. Sums are shown only as "Sum of post reach" and are never unique people.
- Sections: Readout, Audience, Scorecard, Content Lab, Patterns, Trends, Next month, Method & sources.

## Rules that must survive any further work

1. Never fabricate or fill missing data. Missing stays `null` and renders as "—", never 0, and is excluded from medians.
2. De-duplicate by platform + post URL (query string and trailing slash stripped).
3. Do not compare engagement rate across platforms (Instagram includes Saves, Facebook includes Post clicks). TikTok "Reach" is Views.
4. Keep account-level figures (followers) separate from post-level results.
5. Every post keeps its source id and read date; when sources disagree, the later `as_of` wins field by field.
6. Label claims as Fact / Inference / Hypothesis. AI proposals are not the owner's approval.
7. The October reference package (`COFFLORER-UI-Reference`) is design reference only. Its metrics must not be merged; only its cover images are reused.
8. Brand rules: SURYA and Monster are separate brands with separate voices; do not mix them. Dashboard insight text is Thai with English technical terms.
9. Never label the data real-time. The header must show last refresh, last Publer read and latest post.

## Known gaps and open items

- Mixed-age sources: history is a Publer CSV exported 10 Nov; November Instagram/Facebook rows come from Gemini's 14 Nov extraction (7 of 29 re-read from Publer and matched, 22 not re-read); TikTok for 1–10 Nov is still at 10 Nov values. A fresh Publer "Post Insights" CSV export fixes most of this (steps in `README.md`).
- Metrics are cumulative at read time, not age-matched, so month-to-date comparisons lean against the current month.
- The Publer CSV has no Saves or Post clicks; those exist only for November rows.
- Pillar tags are rule-based: "Other" is about 23% of SURYA and 14% of Monster posts. RDM = Random posts (owner-confirmed).
- Cover images exist only for 58 October posts.
- Followers must be re-read from Publer at each refresh, one account per call (parallel calls returned one account's data for all).
- Print styles are written but the printed/PDF output has not been checked.
- The sticky filter bar is tall at medium widths.
- `config/insights.th.json` was written against data as of `written_for_as_of`; revise it when the data changes (the page shows a warning when the data is newer).
- Not yet decided by the owner: whether Happy Halloween (31 Oct), the flood support post (29 Sep) or character birthdays belong in RDM.
